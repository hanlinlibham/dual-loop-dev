# 诊断分期、L1/L2/L3 选档与对抗审阅指南

## 一、先诊断、再分期、每轮只做一件事

面对存量复杂仓库或多阶段路线图时，禁止一上来直接签发大包重构：

1. **基线摸底**：先只读运行一次现有 `typecheck / lint / test`，产出带文件路径、行号与量化测试数的「结构问题 + 功能缺口」诊断表。
2. **风险递增排期**：
   - 先做「让后续每轮改动更便宜、更容易验证」的基础设施（如先修测量探针、先收敛单一动作注册表）；
   - 再按「结构拆包 → 核心数据流闭环 → 界面交互 → 端到端集成」分期推进；
   - 每轮合同明确 `included`、`excluded` 与 `stop_rule`，把顺手想改的相邻问题记入下一轮草稿，不在当轮扩圈。

---

## 二、L1 / L2 / L3 三档门禁标准

| 维度 | L1 轻量档 | L2 标准档 | L3 重型档 |
|---|---|---|---|
| **典型场景** | $\le 3$ 个文件修复、文档/配置同步、无对外行为变化 | 新增功能接口、局部模块重构、常规缺陷修复 | 跨模块拆包、公共 API/协议变更、状态机或异步并发改造 |
| **合同矩阵** | 必填 `required` / 有依据 `not_applicable` | 同左 + 增量测试覆盖要求 | 同左 + 冻结行为等价探针基线 |
| **审阅者身份** | 独立子代理（不与 Executor 同会话） | 独立子代理 | **必须派全新冷审阅者**（禁止连续复用同一长上下文审阅者超过数轮） |
| **反向变异验证** | 可选 | 推荐（针对新增守卫） | **强制**：在 `/tmp` 副本删掉新守卫或回退关键行，确认新测试真实变红 |
| **现场/探针验证** | 静态检查 + 单元测试全绿 | 隔离端口/夹具真实走查 | 逐字节行为探针比对 + 边界/对抗输入独立脚本实测 |

## 三、行为等价探针（L3 核心武器）

重构最危险的错觉是「单元测试全过 = 行为没变」。高可靠重构轮应编写**确定性行为探针脚本**并将其与冻结基线一同列入 `manifest.policy_files`（受 SHA-256 指纹保护）：

- **纯重构轮（零行为变化）**：探针穷举全部路由/入口在合法输入、单字段缺失、组合缺失、越界值下的响应状态与错误码优先级（同时报多个错时先报哪个），要求输出**逐字节等于冻结基线**。
- **功能增量轮（受控行为变化）**：先输出新旧探针快照的精确 Diff，由独立审阅者逐行核对差异**仅包含本轮合同声明的增量**，验收通过后方可将新快照定为下一轮基线。

---

## 四、反向变异验证（Mutation Probing）标准做法

审阅者不能只看「测试跑过了」，还必须验证「如果代码写错了，这套测试真能抓住」：

1. 将当前工作树复制到 `/tmp/review-probe-<id>/`（绝不在原工作树直接改代码！）；
2. 在 `/tmp` 副本中故意注入 3～10 处典型退化（例如：注释掉新加的边界校验、打乱返回顺序、去掉回读核验）；
3. 在 `/tmp` 副本运行测试套件，确认每处退化都能触发明确的业务断言失败（而非因未单独执行或异常吞没而继续全绿）；
4. 测试完毕清理 `/tmp` 副本，将变异矩阵与捕获率写入审阅证据。
